# Reflection

**Design decision.** I used the AgentCore Code Interpreter for the loyalty discount instead of letting the model do the arithmetic. The discount has several dependent steps: points redeemed are floored to the nearest 500 and capped at 50% of the order, then the tier discount applies to the remaining subtotal, then points earned are calculated by category. Language models make small arithmetic mistakes, and a wrong price in customer support is a real cost. I kept a fallback that returns only the tier discount if the sandbox is unavailable, so the agent degrades gracefully instead of failing. For a $200 device order with 4,250 Gold points, the result was exactly $144.00.

**Challenge.** The hardest part was deployment, not agent logic. In the AWS Academy lab, CodeBuild stopped every build within seconds, even a trivial `echo` buildspec, so I ruled out my code and the generated buildspec and switched to a local ARM64 Docker build. That exposed three issues: the toolkit had saved `container_runtime: none` because Docker was not running when I configured it, the generated Dockerfile used Python 3.10 while the project requires 3.13, and `uv pip install .` cannot install a project with multiple top-level scripts. I fixed the config, moved the base image to Python 3.13, and installed from a `requirements.txt`. I also had to put an API Gateway in front of the order-tracker Lambda, because it reads proxy-style events, and add 200 method responses so the Gateway could parse the OpenAPI spec.

**Production consideration.** The Gateway uses the NONE authorizer and the agent connects unsigned, which is acceptable for a lab but not for production. I would use OAuth or IAM authorization, so only the agent runtime can call order and refund tools, and add validation that the caller owns the order before a refund is issued. Memory also stores customer conversations, so I would add PII redaction, retention limits, and per-customer access controls. Finally, I would replace the hard-coded Lambda data with DynamoDB and add observability and alarms on tool errors and latency.
